# Paper2Bench Reproducibility Benchmark

The benchmark measures two things the interface cannot prove by itself:

1. **Extraction accuracy** — how often the heuristic extractor gets a paper's
   training-critical values right, with evidence that actually supports them.
2. **Artifact validity** — whether generated scaffolds parse, carry provenance,
   and agree with their source claims when inspected *outside* the app.

Results are generated by scripts, committed as JSON, and re-run in CI. No number
on this page is hand-written.

## 1. Extraction benchmark

**Pipeline** (all steps reproducible from a clean clone):

```
python3 benchmark/fetch_corpus.py            # fetch papers (arXiv HTML / ar5iv → text)
python3 benchmark/validate_corpus.py         # verify every annotation against the text
npx tsx scripts/benchmark-extraction.ts      # run extractor, compute metrics
```

**Corpus** — first batch: 12 real arXiv papers (landmark CV/NLP training papers),
fetched as plain text. 67 reference claims are hand-annotated against the
extractor's field taxonomy (26 config fields + metric names). Every annotation
must contain a `must_contain` string that is verified to exist in the fetched
text — annotations that cannot be anchored to the text are removed, not fudged.
RoBERTa (1910.01108) was dropped: no usable HTML full text is available.

**Metrics** (computed in `scripts/benchmark-extraction.ts`):

| metric | definition |
| --- | --- |
| correct | reference matched by `field_path` **and** value within tolerance (1e-6 relative; string values compared case-insensitively; numeric prefixes of structured strings like `8x P100` count) |
| wrong_value | reference path extracted, but the value differs |
| missing | reference not extracted at all |
| precision | correct / (correct + wrong_value), over referenced paths |
| recall | correct / references |
| evidence rate | of correct claims, the fraction whose cited evidence sentence contains the annotated value context |

**Current results** (`benchmark/results.json`, regenerate to verify):

```
precision  100.0%   (62/62 — no wrong values)
recall     100.0%   (67/67 references extracted)
evidence    86.6%   (58/67 correct claims cite evidence containing the value context)
```

Per-paper and per-field detail is in `results.json`.

### ⚠️ Read this before quoting the 100%

**These 12 papers were used to develop the extractor patterns.** The number
above is *in-sample*: it is a regression benchmark that locks in current
quality and catches future breakage — it does **not** estimate accuracy on
unseen papers. The honest out-of-the-box measurement on this same corpus,
taken before any corpus-driven tuning, was **precision 53.3% / recall 34.8%**;
the full fix history is in the git log (benchmark rounds 1–4).

To measure generalization, the corpus needs a **held-out split**: papers
annotated by contributors who have *not* read the extractor source, run
through the extractor untouched. That protocol is described in
[CONTRIBUTING.md](../CONTRIBUTING.md) — adding held-out papers is the single
most useful contribution right now.

**Known blind spots** (honest, by construction of the corpus):
- Config tables rendered as images or complex LaTeX are invisible to the
  sentence-based segmenter (ViT's Table 2 was only recoverable because ar5iv
  emits the rows as text).
- Optimizers outside {Adam, AdamW, SGD} (e.g. RMSProp in EfficientNet,
  MobileNetV2) are never claimed — the taxonomy has no path for them yet.
- Papers with two model sizes may surface either config; annotations use
  `value_variants` to say "both are correct".
- ar5iv LaTeX duplication (e.g. `0.90.9`, `256256`, `10−410^{-4}`) is
  deduplicated at capture time; genuinely doubled numbers ≥2 digits could
  theoretically be mis-collapsed (no case observed in the corpus).

## 2. Scaffold validation

```
npx tsx scripts/validate-scaffolds.ts --save
```

Generates scaffolds for three variants (pytorch full / pytorch minimal /
huggingface full) from the demo project and checks **219 items**:

| check | what it proves |
| --- | --- |
| YAML parses (js-yaml) | the generated config is loadable by real tooling |
| JSON parses | evidence files are machine-readable |
| Python `ast.parse` (python3) | every generated module is syntactically valid |
| provenance marker present | every file carries its P2B provenance header |
| TODO(p2b) traceability | unknowns are explicit, not silently defaulted |
| requirements pin syntax | dependency lines are pip-parseable |
| config ↔ claim consistency | config values equal the evidence-ledger claims they came from |
| secret scan | no credentials in generated artifacts |

**Current results** (`benchmark/scaffold-validation.json`): 219/219 checks pass.

**Blocked by design** (never claimed as passed): executing the generated
training loop (torch + accelerator required) and an end-to-end training smoke
test. Paper2Bench's honesty rules forbid describing a generated scaffold as a
reproduced model — the scaffold is a starting point with explicit unknowns.

## 3. Core logic suite

```
npx tsx scripts/verify-core.ts    # 102 assertions
```

Covers heuristic extraction patterns, run importers, comparison semantics,
scaffold determinism, validation honesty, compute estimation, readiness scoring,
and workspace lifecycle. CI runs the suite, the extraction benchmark, the
scaffold validation, and the CLI smoke test on every push.

## Adding a paper

1. Append `{id, title, venue}` to `PAPERS` in `benchmark/fetch_corpus.py`, run it.
2. Grep the text for the values you remember; annotate only what the text
   confirms (`benchmark/annotations/<id>.json`, `must_contain` required).
3. `python3 benchmark/validate_corpus.py` must pass.
4. For held-out papers: do **not** read the extractor source first; note the
   held-out status in the annotation file and the PR.
